# Portal Design System

> Shared tokens, portal shell, and portal-neutral components live in the versioned `@raisd-campus/design-system` package. Read the [canonical component guide](../../design/component-library.md) and the installed `node_modules/@raisd-campus/design-system/docs/components.md` catalogue for exact APIs ([0.6.0 online](https://github.com/raisd-campus/design-system/blob/v0.6.0/docs/components.md)). This document retains student-specific composition and responsive rules.

## Shared disclosure and avatar refinement

Shared package 0.6.1 adds a pointer cursor to enabled accordion triggers, preserving disabled interaction and header geometry. `AvatarFallback` accepts `surface="subtle"` to use the darker surface-subtle token on a surface background; shared chat rows use this option. Other avatar sizes and image behavior are unchanged. Read-only file values compose `DetailField`'s standard readOnly label/value columns with a read-only `FileUploadField` value; stacked presentation remains an explicit variant.

## Direction

The current portal is a dark-only responsive product for student-facing browser layouts from 375px through 1440px. Semantic tokens and reusable components are the supported way to express visual decisions. Development-only `/dev/*` routes provide basic phone usability at 375px and 430px; individual demonstrations remain outside the full student-facing responsive acceptance standard.

The [published design system catalogue](https://raisd-campus.github.io/portal-api-docs/design-system/) shows released shared components and student-owned patterns in static mock-data captures. Use the package catalogue and installed declarations for exact APIs. Development-only Scenario, Admin Actions and Data Model tools retain their own responsive layouts.

## Responsive layout rules

- Package `usePortalLayout()` is the single UI-only source for `phone`, `tablet`, and `desktop` layout mode. Phone is below 768px, tablet is 768–1199px, and desktop begins at 1200px. The shared `PortalShell`, `PortalSidebar`, `PortalHeader`, `PortalAccount`, `PortalMain`, `PortalPageContent`, and navigation components own the frame; the student portal supplies route trees, profile issues, Community content and resizing. These modes do not change route contracts, Portal API records, or workflow state.
- Main page gutters are 16px on phone, 24px on tablet, and 48px on desktop. The shared portal shell measures the browser layout viewport and rechecks it after field blur, viewport resize and orientation changes so iOS expands the shell again after its keyboard closes. The main portal area remains the one page scroller and includes safe-area padding. Student pages must not create document-level horizontal overflow.
- Phone uses a full-viewport navigation drawer with flush square outer edges, full-width navigation/footer content, and a 300ms ease-out left-edge slide without panel fading. Tablet uses the 3rem icon rail with visible tooltips and keyboard-accessible flyouts for Academic, Profile, and Services children. Desktop uses the full navigation and its rounded floating frame. Community is a full-screen overlay on phone and tablet that uses the same left-edge, slide-only 300ms motion and exposes one visible overlay title; its mounted content is moved between hosts so the current layer, conversation, drafts, attachments, pending sends, and scroll positions survive layout changes. The overlay header centres its title and 44px close target in the same 68px row, while the phone composer centres its attachment control, text field, and send control in the single-line row. It remains a docked, resizable panel on desktop. Phone header controls use a burger icon for navigation and a chat bubble for Community while retaining their accessible action names; because they are touch targets, they have no hover fill while preserving focus-visible feedback.
- Tab rows stay on one horizontally scrollable line and reveal the selected or focused tab. On phones, every production tab viewport hides vertical overflow and accepts horizontal panning only. `SegmentedTabs` keeps its rounded `surface-subtle` frame solid, while only the labels, dividers, and active indicator scroll within it. Four-or-more-item strips reserve enough width around longer labels to keep text clear of the inactive dividers. The component re-anchors the selected segment after resizing and browser page restoration so Safari cannot restore the labels with the selection outside the visible strip. Both `SegmentedTabs` and `TabbedPagePanel` fade their scrollable tab content at the edge that has more tabs available, following the current scroll position without fading the owning frame or panel. At constrained widths, shared summary cards, detail fields, forms, action bars, and dialog actions stack instead of compressing their content. `DetailField` uses the enclosing panel/container: up to 30rem its label sits above a full-width value or editor with an 8px gap; wider containers retain the 160px label column. The catalogue includes a constrained example.
- `FormGrid` owns two-, three-, and four-column form layouts. It collapses to two columns and then one column according to its container, and consumers must not recreate those rules locally.
- `DataTable.compactCards` is for record-oriented lists such as forms, document checks, directories, and submissions. It renders labelled cards on phones with normal-weight title-colour values while retaining the semantic table at larger sizes. A column marked `compactCardAction` leaves the labelled details and joins the row-selection action in one shared bottom action row; View details appears first and fills the remaining width while fixed icon controls follow at the right edge. `DataTable.minTableWidth` is for ledgers, grades, calculations, and comparison tables; it keeps the semantic table inside a keyboard-focusable horizontal scroll region. On phones, the shared table viewport accepts horizontal panning only and fades the table content at each edge where more columns are available; the owning border and frame remain solid.
- Standard single-line `Input`, `DropdownSelect` and `DatePicker` fields use 36px height, 14px text and 20px line height in every view and pointer mode. Textareas retain 14px text and multiline height. Other coarse-pointer controls retain their 44px targets, including rating labels and the Community composer field. Phone fields retain their normal shared typography, including the 14px chat composer body size; the document viewport requests zoom suppression with maximum-scale=1.0 and user-scalable=no, which also restricts manual scaling where honored. Physical iPhone Chrome and Safari focus, keyboard dismissal and orientation checks remain necessary because browser scale handling varies. The composer retains a 44px minimum height and balanced vertical padding on touch devices. Popups, sheets, and document viewers remain inside the visual viewport with independently scrollable content and reachable headers and footers.
- Responsive browser acceptance covers Chromium at 375, 390, 430, 768, 1024, 1280, and 1440px and focused WebKit checks at 375, 768, and 1440px. Dedicated landscape compositions and physical-device certification remain separate work.

The mobile review and regression coverage are recorded in [the September 2026 mobile audit](audits/2026-09-22-mobile-responsive-audit.md). Announcement list thumbnails use 64px by 48px on phones, with a 12px gap to the title and chevron; wider views retain 112px by 64px. Two-column Services information tables wrap inside the available width; only wider comparison tables receive a minimum scroll width. Lecturer ratings below a 30rem review container place the Poor/Excellent endpoints above five evenly spaced targets.

## Token rules

Online Forms follows Finance's nested detail rhythm, Portfolio's editable-field styling and Lecturer Review's confirmation popup. Its Available Forms/My Forms tabs use the existing `TabbedPagePanel` with plain labels; unread reviewer updates sit in a separate warning `IssueCard` above the panel instead of a tab counter. Shared `UnreadBadge` remains available for contextual navigation counts so form counts are not called messages. Available Forms uses the shared banner slot, full-width `SegmentedTabs` and `LinkedList`; My Forms retains the bordered `DataTable` pattern. Form details use a `Prefilled Details` `DetailSectionCard` and route-level actions use `PageActionBar`.

`FileUploadField` owns distinct empty, uploaded, multiple-file, and read-only states inside one dashed container. Uploaded metadata sits in a raised, centred file tile with its filename, file size and accessible remove control inside that boundary; replacement uses the shared underlined link treatment and no source or selection label is shown. Guidance and validation follow the shared 8px field rhythm. Its consumer owns file selection, validation and storage; Finance keeps its existing single-proof 10 MiB policy while Online Forms supplies field-specific limits and optional MIME restrictions. Submitted Online Forms and university-held evidence use the read-only state so metadata remains legible without edit or delivery controls. Hidden native file inputs are excluded from tab order; the visible picker receives focus and validation associations. Date/select triggers accept explicit IDs and error descriptions. When a route workflow requires a structured document submission, its progress step links to the existing Online Forms lifecycle and reflects the form status; it does not embed a second one-off uploader inside the progress hub.

From package 0.6.0, `ChatComposer`, `ChatMessageRow` and `DateDivider` presentation comes from `@raisd-campus/design-system/system/chat-composer` and `system/chat-message`. Student compatibility adapters under `components/system` retain API sending, validation, draft ownership and file resources for Community and Online Forms. Composer outer spacing is opt-in: Community retains its footer treatment while Online Forms uses a full-width composer whose divider reaches the edges of its borderless `surface` case-message inner section; reviewer avatar fallbacks use `surface-subtle`. Phone controls retain the design system's normal typography, including the shared composer's 14px body text, while viewport metadata disables browser zoom. Draft disposal is shared, pending sends preserve preview ownership until settlement, and sent previews belong to the current portal session. Case messages sit outside form details under the same page-title hierarchy, with a closely grouped explanatory label and a 48px inter-panel gap; they contain no delete controls, and closed cases replace the composer with a readable explanation. The published design system catalogue includes form-field, case-message and badge examples.

- Use five neutral elevation tiers directly in components: `background` (tier 0), `surface-subtle` (tier 1), `surface` (tier 2), `surface-raised` (tier 3), and `surface-elevated` (tier 4). Use `surface-subtle` for quiet inset content such as charts; dashboard module cards use `surface`; Academic module cards, grade accordions, timetable periods, Calendar agenda/details rows, and standard cards use `surface-raised`; overlays use `surface-elevated`. Use `surface-hover` for neutral interactive hover and selected states rather than a component-specific alias.
- Use direct global surface, brand-palette, and status tokens in components. Retain semantic text and intent tokens only where they communicate meaning, such as `brand`, `success`, `destructive`, and `warning`. The fully opaque `brand-cyan`, `brand-sky`, `brand`, and `brand-indigo` palette is for branded hierarchy and non-status breakdowns; do not use it to communicate success, warning, or destructive meaning. Typography uses a separate hierarchy: `title` for highest-emphasis content, headings, and card labels; `body` for readable content; and Muted for metadata. The implementation name is `muted-foreground` to distinguish it from the separate muted surface token.
- `success`, `warning`, and `destructive` form one balanced status palette: teal-green for positive or confirmed state, amber for attention or due work, and coral-red for overdue or destructive state. Semantic surfaces use the faded status colour, while visible text and icons use the accessible text role. Filled brand, success, warning and destructive controls use the separate `brand-solid`, `success-solid`, `warning-solid` and `destructive-solid` surface roles with light foreground content. This split keeps small semantic text readable on dark surfaces without making filled controls too light for their white labels.
- `Badge` is the reusable compact 400-weight status pill. Its standard `sm` size is 20px high; its `lg` size is 32px high with 12px horizontal padding and 14px body copy for prominent status rows and summary pills. The shared student summary uses the large `secondary` Badge with the `surface-elevated` background override. Its default brand-blue, `success`, `warning`, and `destructive` variants use faded semantic backgrounds with matching solid label copy. The `success-solid`, `warning-solid`, and `destructive-solid` variants use their solid semantic surfaces with light copy for a Badge inside a same-colour faded summary card; they do not use feature-specific status styling.
- `AttentionIndicator` is the reusable non-interactive 20px status marker for a compact action-needed signal. It uses the solid `warning` circle, a white exclamation mark, and an accessible label so colour is never its only meaning. Module Materials places one beside a current or completed week Badge when derived assessment state requires attention.
- Issue cards use a 12px radius and solid severity surfaces: warning cards retain the amber `warning` surface with light content; destructive cards use light content on `destructive-solid`. Amber is for upcoming or due-today work; red is for overdue work. Their hover surface darkens immediately to the same 80%-intensity treatment as the destructive `Action required` button, and they use a pointer cursor as the current card affordance.
- Neutral buttons, cards, menus, sidebars, text fields, and selects use `surface-hover` for their gray hover background. Brand, destructive, timetable, and media-overlay states retain their own semantic hover treatments. Hover changes are immediate: do not add colour, brightness, or opacity transitions for hover feedback.
- Timetable periods use the shared neutral system directly: scheduled classes use `surface-elevated`, while open periods use `surface-raised` at reduced opacity. Non-current class hover uses `surface-hover`; the surface background shows through their shared spacing. Each visible hourly label begins with a compact vertical marker using `muted-foreground` at reduced opacity.
- `TimetableCard` uses minute-based columns under hourly labels on tablet and desktop. The default 07:00–19:00 extent expands for early/evening classes and scrolls within the card when needed, preserving the 16px inset and existing colours. Expanded ranges reserve 3.25rem per hour plus the day label; normal ranges retain their compact width. Phone renders the same classes as a day selector and chronological agenda. Accessible class names include exact times, and the published design system catalogue includes a 09:15–09:45 session and a 20:00–21:00 session.
- Short timetable classes (under one hour) use 4px horizontal content insets so padding does not consume their label space; longer classes retain 12px insets. Truncated metadata remains available through the shared tooltip and accessible class name.
- Performance charts use global roles directly: success for rising values, destructive for falling values, muted foreground for unchanged values, and border for chart reference lines. Trend meaning is reinforced by visible values and labels rather than colour alone.
- Calendar event identity reuses direct global roles: brand for classes, warning for assignments, destructive for exams, success for confirmed meetups, title for holidays, and the purple `registration` role repeated across every date in the module-registration window. The centred legend and agenda kind labels repeat the meaning so the dots never communicate category alone.
- Service identity accents (`service-amber`, `service-pink`, `service-blue`, and `service-red`) are global tokens reserved for their named student-service contexts. They are not status colours.
- Scrollable regions use the global `scrollbar-track`, `scrollbar-thumb`, and `scrollbar-thumb-hover` roles. Firefox uses the standard scrollbar properties; Chrome, Edge, and Safari use the matching WebKit selectors.
- The main portal scroller reserves a stable scrollbar gutter so route content keeps the same width whether that page overflows or not. The document root is overflow-hidden: expanding a resizeable field keeps overflow in this one portal scroller rather than creating a competing document scrollbar. Main route content retains a 12px bottom inset (while preserving its 48px top inset), leaving 4px of visual breathing room above the sidebar's bottom controls.
- Every pathname, query-string, or hash change immediately resets the main portal scroller to the top. The same rule applies to browser Back and Forward navigation; local interactions that do not change the URL retain their scroll position.
- Use the shared Tailwind spacing scale. Add layout tokens only for stable application dimensions such as page gutters, content widths, and sidebar widths.
- Dashboard section-card content uses 16px (`p-4`) padding. This includes module cards, article text and metadata areas, and the timetable surface; compact timetable period content remains an intentional exception.
- Use typography utilities for all application text instead of ad-hoc font sizes. The supported utilities are `type-label` (spaced uppercase), `type-label-normal`, `type-title`, `type-section`, `type-section-lg`, `type-body`, `type-metric`, and `type-badge`. Both label utilities use the 12px regular (400) style and define only size and weight; each component applies its own colour token according to meaning. Editable form and detail-row labels use `type-body text-title` at 14px, followed by the standard 8px field gap (`mt-2`); reserve `type-label` for metadata or group headings, not interactive field labels.
- All actionable button and tab labels use regular (400) weight. Emphasis belongs to content hierarchy and semantic titles, not to an action's default, active, or selected state.
- Standard labelled `Button` actions use one 36px (`h-9`) height across default and large call sites; the standard square icon size is also 36px. Explicit compact icon-only controls such as dialog close, sidebar toggles, and timetable removal retain their named compact variants, while inline link-style actions may use content height. The published design system catalogue's Button examples consume this shared rule directly.
- `type-section-lg` is the 24px, medium-weight, title-colour heading for a nested content title such as a module name. It appears in the Typography explorer above the standard 18px section style.
- `type-title` is the 16px, medium-weight, high-emphasis title style used for contextual card headings such as the selected `Semester 4`. `type-body` uses the general body-text colour rather than a sidebar-specific alias. The smallest supported portal text is 12px; do not introduce text below 10px.
- Use shared radius, shadow, duration, and easing values.
- Raw white, black, hexadecimal, or arbitrary values are allowed only for genuine media overlays or externally defined brand colours; otherwise introduce or reuse a semantic token.
- Keep `.dark` on the root for component-library compatibility, while treating dark as the only supported theme in this phase.
- Tooltip uses the tier-3 `surface-elevated` with `border` and the shared `floating` shadow so it stays distinct above lower-elevation content. Use it for supporting information that is otherwise visually clipped, not as a replacement for visible labels or controls.
- The published design system catalogue separates global tokens (surface tiers, typography, and shared roles) from component-specific tokens such as the cross-browser scrollbar. Components use these direct tokens rather than colour aliases.
- `npm run check:tokens` prevents component code from reintroducing the retired `foreground`, `primary`, `sidebar`, `card`, `popover`, `secondary`, `accent`, `hover`, or `unread` colour aliases. Layout-only variables such as `--sidebar-width` remain valid.

## Component layers

`PagePanelLayout` owns the shared rounded surface used for an optional navigation row, an optional flush banner and then content. When navigation is supplied, tabs or breadcrumbs sit above one divider; when omitted, the banner begins the panel without an empty header or divider. Content insets are standard (16px), wide (60px), or none; standard is the default. Wide content uses the standard 16px inset below 768px and expands to 60px from tablet upward. Announcement details use breadcrumb/wide mode, while University Policies uses the navigation-free banner mode. `TabbedPagePanel` composes this frame for its tabs, so Services uses the same structure while Profile and Finance retain their existing default spacing. The published design system catalogue shows breadcrumb, tab and navigation-free variants.

`LinkedList` owns phone summary density across every consumer: descriptions clamp to two lines below 768px and remain complete at wider sizes. Its icon, thumbnail, disabled explanation, chevron, focus and full-row action semantics are unchanged.

`QueryErrorState` is the shared student-facing read-failure state. It uses the same centred 12px-radius geometry as `EmptyState`, a neutral surface with the global destructive icon treatment, an assertive labelled alert, and an optional secondary **Try again** action. Route copy describes the information that is unavailable and what the student can do; it must not mention adapters, mock data, APIs or implementation details. Feature-owned follow-up actions may be composed beside retry when the route has an exact safe destination. The published design system catalogue includes the standard retryable state.

`TabbedPagePanel` supports opt-in `scrollable` tabs for longer lists, used by Services. It keeps a single row, standard 16px insets and the shared active indicator while revealing selected/focused tabs on navigation and container resizing. Reduced-motion preferences remove the indicator transition duration. Its optional `contentInset` delegates to `PagePanelLayout`; existing consumers retain the standard default. A consumer whose complete tab body is one self-framed table may explicitly select `none`, allowing that table to meet the panel edges without automatic content inspection. The published design system catalogue includes a constrained-width seven-tab example with keyboard navigation.

Services body content intentionally reproduces the source content region beneath the unchanged banner. Feature-owned `ServicesSectionContent` composes typed text, nested stack/split groups, media cards and `DataTable`; uncomposed sections continue to use `ContentSection`. Services selects the shared panel's no-inset mode, and its own body supplies 60px desktop padding, 32px section/column spacing and source-style dividers directly on the panel surface. It does not create a second page-sized rounded/gradient body container, nor alter `CardGrid`, `ContentSection`, `DataTable` or their other consumers.

The named Services container switches below 640px to 48px vertical/32px horizontal body padding and source phone order. Photos use centred cover cropping at 360px on wide containers and 220px on narrow containers; split-column photos stretch alongside text. Dish cards have overlaid captions, 110px desktop/140px narrow height, and three/one columns respectively. Illustrated benefit cards keep two columns and 60px icons. Failed media reserves the same geometry and exposes its alternative text. The department contact block is removed.

Source tables reuse semantic shared tables with feature-scoped cell borders, centered values and a contrast-checked caption strip using `--service-table-caption`. Hours use 40/60 columns; rates use equal columns. Font family, heading and body classes remain portal styles. The published design system catalogue captures the Dining composition and Accessibility empty-content treatment. For local interactive inspection, `/dev/services-content?slug=dining` remains a query-backed isolated responsive canvas excluded from production.

| --- | --- |
| `@raisd-campus/design-system/ui/*` | Cross-portal primitives and semantic tokens. |
| `@raisd-campus/design-system/system/*` | Portal-neutral cards, tables, fields, panels, media and navigation patterns. |
| `components/ui` | Student shell controls that depend on this app's viewport hooks. |
| `components/system` | Student workflow composition, route adapters, Community draft behaviour and other app-bound UI. |

Promote a visual pattern into `design-system` when it is reusable without student contracts, routes, queries or workflow decisions. Import released components from package subpaths; never copy their source into the student portal. Keep single-use components beside their feature.

## Interaction and accessibility

The repeatable CAP-35 engineering audit uses `@axe-core/playwright` against WCAG 2.2 A/AA tags on representative production routes at 1280px and 1440px, both mock student scenarios and key dialog/Community states. Responsive suites additionally cover keyboard navigation, focus return, touch target sizing, overlay dismissal, tab visibility, overflow, reduced motion, and reachable workflow actions. The product decision to disable browser zoom while retaining normal component typography is a documented WCAG 1.4.4 exception; automated axe runs exclude only `meta-viewport` and continue to fail on every other detected rule. Automated results support the review but do not constitute formal conformance, screen-reader certification, or physical-device testing. See [the dated audit report](audits/2026-09-09-accessibility-audit.md).

- The portal-wide menu header remains sticky while the main portal area scrolls, with a background layer that keeps its controls readable; its profile section shares the content's scrollbar-aware right gutter.
- The main header uses the shared page breadcrumb, which reflects the active top-level route and its navigation hierarchy. It replaces the former programme-and-year summary.
- The top-menu avatar is a direct Profile > Personal action. The sidebar's `Log out` control remains the sole visible frontend-only logout placeholder until authentication enters scope.
- Active student account issues add a solid destructive `Action required` button immediately to the right of the student's profile picture on tablet and desktop. On phone it becomes a labelled, full-width action below the header row, keeping the next step readable and easy to reach. It uses the same filled warning triangle treatment as destructive module issue cards, a pointer cursor, and no press-position movement; it navigates to Profile > Personal. Clear and attention states appear in static `StudentProfile` captures in the published design system catalogue.
- Interactive visuals must use a button, link, or appropriate accessible primitive.
- The chat composer uses a compact raised-surface menu-style icon Button for Add attachment, retaining the existing file-picker behavior.
- The floating portal sidebar keeps Navigation and Community as adjoining `surface` columns separated by a full-height shared border. Main navigation rows, accordion triggers, and Navigation's static bottom `Log out` placeholder use the same non-shrinking 36px raised-surface row treatment; the footer keeps its edge-to-edge divider and nested navigation links retain their compact child-row treatment. Expanded Navigation overflow stays in its scroll region rather than compressing row heights. An active Chat Composer uses the same footer structure, divider, padding, and 36px control row so it aligns exactly with Navigation's Log out footer.
- Enabled buttons, links, tabs, menu choices, and other button-like controls use the pointer cursor globally. Disabled controls keep their disabled affordance. Module cards, timetable class cards, and module-linked Calendar agenda cards use this shared interactive affordance for Module Details navigation.
- Keyboard focus must remain visible.
- Icons require accessible labels when they carry meaning and must be hidden when decorative.
- Hidden file inputs retain explicit accessible names even when a labelled button opens the native picker. Controlled dialogs restore focus to their originating action. Dynamic errors and completion states use the appropriate alert/status semantics already owned by their shared or feature components.
- Loading, empty, error, disabled, selected, hover, and focus states must be represented in the catalogue when supported.
- Colour must not be the sole carrier of status.
- The timetable presents one full-detail tooltip when either its class title or location is clipped; cards whose text fits do not show a tooltip. Online timetable classes additionally show the shared laptop indicator with an `Online Class` tooltip. Every class card is a keyboard-accessible Module Details action using its timetable record's module and semester IDs.
- `ArticleCarousel` uses native horizontal scrolling: trackpad sideways scroll and mouse drag move the same card strip, while the previous/next buttons provide an accessible alternative. Its title, accessible region label and View all action are configurable; Dashboard retains **News and Announcements** with View all, while the Announcement overview uses **Important Announcements** without the redundant link. Its scrollbar is visually hidden without disabling scrolling.
- The custom scrollbar applies globally to horizontal and vertical overflow. Forced-colour mode uses the operating system scrollbar colours to preserve accessibility.
- `IssueCard` is the reusable portal pattern for an issue summary. Warning cards use light content on `warning`; destructive cards use light title copy on `destructive-solid`. Severity is also expressed in visible text. The decorative alert icon is a light triangle with a small severity-coloured alert mark, centred in a 36px rounded square. Issue labels use regular 12px text, and the icon-to-copy gap is 8px. It supports start- and end-icon placement plus an optional accessible button action. Module assignment and exam issues use that action to open the exact learning-item detail; Online Forms uses a full-width warning card above its tabbed panel to open My Forms when reviewer updates are unread; static Profile examples retain the non-button presentation. Module cards use a non-interactive surface wrapper with separate module and issue actions, avoiding nested buttons while keeping full keyboard access. `OnlineClassIndicator` is the shared brand-colour laptop icon with its `Online Class` tooltip and explicit image semantics; Module cards and online timetable class cards use it. A current online timetable class switches the icon to the brand foreground for contrast against its brand background. Physical delivery remains visually unmarked but is included in the card's accessible name.
- `UnreadBadge` is the compact sidebar-specific count for programme and module conversation summaries. It uses the dark `background` surface, regular label weight, exact accessible unread copy, hides at zero, and caps visible three-digit counts at `99+`. It never displays roster size; Messages keeps its smaller avatar-attached unread treatment. The published design system catalogue shows the summary badge with other status controls.
- `DetailField` is the reusable record row used by Profile. Its `readOnly` variant top-aligns its high-emphasis value beside the label; `readOnlyStacked` places its label above the value for compact metadata columns; and `editable` vertically centres a supplied form control and optional destructive validation message. Every variant uses shared borders and 14px body-label typography; side-by-side variants use a 160px label column. They appear in the published design system catalogue.
- `DetailSectionCard` is the reusable transparent bordered wrapper for related detail rows. It has an 8px radius; its title and content areas each use 12px padding and are separated by a shared-border divider. Profile uses it for General, address, and emergency-contact groups; it appears in the Forms catalogue.
- `InnerSection` is the reusable quiet grouping inside a larger panel. Its default uses an 8px radius, border and 12px padding without adding a background or heading. Its opt-in borderless `raised` surface keeps related preparation content visually separate without adding another frame; Online Forms keeps the **Before you start** heading, explanatory copy, and any required-document list inside that surface, with eligibility guidance and the action bar as following siblings. The borderless `surface` variant supports the rounded Online Forms conversation, which can opt out of its default padding when a child composer needs edge-to-edge dividers. Module Details uses the default for metadata fields and the assessment outline; Module Registration composes it with `surface-subtle` to group the confirmation total. It appears in the Module detail patterns catalogue and published design system catalogue.
- `IconButton` is the reusable 36px square action primitive. It composes the bordered transparent secondary Button treatment, supports a native disabled state, and can add a shared Tooltip for an otherwise icon-only action. The published design system catalogue shows enabled and disabled examples. `FileLink` is the reusable underlined brand filename control with no icon; it changes to the high-emphasis title colour on hover. Until the Portal API provides an authorised file URL, its click is deliberately a no-op.
- Performance chart cards use Recharts, the quiet `surface-subtle` inset tier, shared 16px card padding, semantic chart tokens, system typography utilities, and the gray hover role for semester controls. Point values stay visually quiet until hover, when a semantic popover tooltip identifies the semester, metric, and value. Tooltip position changes are immediate rather than animated, so it follows the chart pointer without lag. The labelled chart container and pressed/disabled semester buttons provide the accessible chart experience; Recharts’ duplicate SVG focus layer is disabled to avoid a browser focus outline on mouse click. The selected-semester heading and active x-axis semester label use the high-emphasis `title` text colour. Academic Performance supplies an optional secondary `View breakdown` action aligned opposite the current value; dashboard cards omit the action. The detailed popup is a separate deferred production chunk.
- The performance loading state reserves the same two-card grid and uses the same quiet `surface-subtle` tier plus shared `Skeleton` surfaces while the near-viewport chart chunk loads. The published design system catalogue shows this state beside the completed chart card.
- `TabbedPagePanel` is the shared route-tab surface composed through `PagePanelLayout`: its tab row and default content region each own a 16px inset, with one `border` divider between them and clipped 12px corners. Opt-in scrolling tab rows use `scrollbar-hidden`, retaining pointer/keyboard scrolling and focused/active-tab visibility.
